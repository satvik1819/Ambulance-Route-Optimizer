# Algorithms and decision logic

## Synthetic graph mode

The original synthetic workflow remains based on Dijkstra's algorithm. Each edge carries distance, travel time and a road identifier. Dijkstra minimizes total edge travel time. Hospital selection filters non-operational hospitals and those with no emergency beds, then scores reachable candidates using travel time, available beds, emergency beds and the existing emergency-capacity field. Incident rerouting creates a graph view with the selected road IDs removed and reruns Dijkstra.

## Real-world map mode

The real-world workflow is intentionally separate from the synthetic graph because the included `nodes.csv` coordinates are synthetic grid values, not geographic coordinates. Nominatim resolves a searched address. Overpass discovers nearby named hospitals and their available OpenStreetMap tags. OSRM calculates road-network travel-time and distance estimates and returns the selected route geometry. Folium/Leaflet renders the map.

Candidates are first limited to the nearest hospitals by straight-line distance to keep public routing requests bounded. Their ranking is then based on OSRM road travel time, with a small tie-breaker when relevant specialty tags are explicitly present. Immediate urgency disables that specialty tie-breaker so travel time takes priority. Missing specialty tags are treated as unknown, not as proof that a hospital lacks the capability. Live bed availability, clinical suitability and actual hospital acceptance are not provided by these services.

## Limitations

- OSRM's public demo endpoint is not a live-traffic service.
- OpenStreetMap coverage and hospital specialty tags vary by region.
- The real-world route is generated by OSRM, not by the project's Dijkstra implementation; the UI labels these as separate workflows.
- This is an academic decision-support prototype and must not be used as a real emergency dispatch or clinical triage system.
